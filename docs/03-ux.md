# UX & design system requirements

## Doctrine

**Editor is sacred. Agent is first-class. Apply is explicit.**

Analogy: VS Code editor + Claude/Cursor sidebar — not a dashboard, not a gen form on top of the page.

---

## Information architecture

```
┌─ top bar: project name · chapter · Continuity · Focus · Agent toggle ─┐
├─ binder (left, collapsible) ─┬─ manuscript (center) ─┬─ agent (right) ─┤
│  chapters                    │  clean type surface   │  chat           │
│  sheets by kind              │  continuity marks     │  context chips  │
│                              │  no gen chips         │  tool runs      │
│                              │                       │  apply queue    │
└──────────────────────────────┴───────────────────────┴─────────────────┘
```

| Region | Default | Focus mode |
|--------|---------|------------|
| Binder | Open or remembered | Hidden |
| Manuscript | Always | Full width |
| Agent panel | **Open OK** (power default) | Hidden |
| Top bar | Thin | Minimal |

### Reading profile (paper)

**Bookmark on the manuscript** (not top-bar chrome) cycles **Day → Sepia → Mint → Night**.  
Sets `data-reading` on `<html>` → `color.paper` / `color.paperInk` only; chrome stays `data-theme`.

- Control styled as a small **tab/clip** on the page corner (`--size-reading-btn`)  
- Meta (words · characters) sits **under the title**, not at the card footer  
- Paper is an **open column**: no closed bottom edge; outer `.manuscript` scrolls  
- Theme icon (top bar) flips chrome day/night and syncs paper to day/night defaults

## Surfaces

### Manuscript

- Measure ~65–75ch, generous line-height  
- Continuity marks: yellow (soft drift), red (hard conflict) — semantic colors only  
- Mark interaction: hover/focus shows reason; jump to sheet/fact when linked  
- **No** inline “generate” buttons on caret or selection balloons in P1  
- **Page surface:** A4 **ratio** only (`min-height = width × √2` via container `cqw`) — not physical mm; width = `manuscript.pageMaxW*`; long text grows past one page, outer reader scrolls  
- **Reading control on paper:** **&lt;1366** = round seal top-right *inside* page; **≥1366** desk = right-edge ribbon. Profile colors from tokens. Not top-bar chrome.  


- **Meta:** words · characters under title  
- **Responsive rails:** `size.binder*` / `size.agent*` scale lg→2xl; page width tokens scale slightly on large screens  
- **Scrollbars:** thin on rails/panels; **hidden on manuscript paper** (wheel/keys still scroll)
- **Empty chapters:** `EmptyState` with hint + **New chapter** (same action as binder)
- **Skip link:** first focusable control skips to `#workspace` (manuscript or graph)  



### Craft tags (chapter “what this page is doing”) — **useful with constraints**

**Verdict: yes, useful** for serial authors and newbies — as **soft metadata + review input**, not as a second nag system like AutoCrit.

| | |
|--|--|
| **What** | Small chips / sticky strip on the chapter (top of manuscript or under title): e.g. `char-dev`, `plot-progress`, `twist`, `world-build`, `relationship`, `setup`, `payoff`, `breather` |
| **Who sets** | Author manual **and/or** agent suggests after a run → user Accepts tags (same ownership model) |
| **Look** | Quiet chips (`text.xs`, `color.surfaceRaised`, `color.border`) — **not** mark-yellow/red (those stay continuity-only). Optional tiny icon per tag from a fixed set |
| **Sticky** | Thin bar under chapter title is OK; must **hide in Focus mode** or collapse to one “n tags” affordance so it never eats the page |
| **Not** | Big footnote wallpaper; permanent traffic-light “your chapter is bad”; more than ~5–7 visible chips without overflow menu |

**Why useful**

- At-a-glance “what is this chapter for?” when skimming a 80-chapter binder  
- Gives Review agent structured targets (“you tagged twist but none detected”)  
- Newbie education without a course: empty tags → agent can say “most chapters need at least progress or character pressure”  

**Why it can hurt (avoid)**

- Same failure mode as revision tools mid-draft: shame chrome while writing  
- Fake precision (agent over-tags every para)  
- Color collision with continuity marks  

**Phase:** optional light **manual tags P1.5**; agent-suggest + chapter-end craft check **P2** with Review. Domain: `chapter.craftTags: string[]` (closed enum in code).

### Binder

- Chapters ordered list + add  
- Sheets grouped by kind; create manual **or** “Ask agent…” (opens agent with create-sheet intent)  
- Select sheet → detail in binder stack or center auxiliary view (decide in build; keep simple)

### Sheet detail (character / lore / world / org)

| Element | Phase | Notes |
|---------|-------|--------|
| Name, kind, aliases, summary, notes | P1 | Core |
| Facts list (key/value + statement) | P1 | Incl. `relationship` kind when relevant |
| **Portrait / icon** | **P1.5 / P2** | Image or emoji/icon on card; local file or URL; empty state placeholder; does not block P1 text sheets |
| Lore-aware field hints | P1–P2 | Optional suggested slots (appearance, wound, faction, oath…) from agent — **user chooses**; not a locked RPG form |
| Pending strip | P1 | “Suggested from manuscript / agent” under sheet |
| Graph “show connections” | P4 | Jump to canvas focused on this node |

Portrait tokens later: fixed aspect thumb (`size` in TOKENS when implemented); never mark colors for chrome.

### Agent panel (Claude-extension shape)

- Transcript (user / assistant / tool)  
- Composer input  
- Context chips: current chapter, selection, @bible, @sheet  
- Run shortcuts: Continuity, **New sheet…**, (later) Review, **Research**, Co-write  
- **Apply queue:** manuscript snippets with Apply / Dismiss  
- **Proposal cards:** bible Accept / Edit / Reject (incl. multi-fact “sheet pack”)  
- Newbie: empty-state tips in panel, dismissible — not a forced tour  
- Collapsible; state remembered  

### Research panel (P3) — clean but powerful

Dedicated surface (agent tool mode or sibling panel), **not** a messy chat dump:

```
┌─ query ─────────────────────────────────────────┐
│ pins / sources │  results + citations            │
│ saved notes    │  [Propose to sheet] [Pin]       │
└────────────────┴────────────────────────────────┘
```

| Do | Don’t |
|----|--------|
| Sparse chrome, strong hierarchy | Five competing AI widgets |
| Citations required on cards | Unsourced “lore dumps” into canon |
| One primary action: Pin / Propose | Auto-write chapter from research |
| Works with keyboard | Hover-only critical actions |

Steal **calm** from Obsidian/read modes; power = filters + pins + propose — see [design/REFERENCES.md](./design/REFERENCES.md).

### Graph / canvas (P4)

- Full-width or center slot replacing editor temporarily (editor tab remains)  
- Nodes use sheet portrait/icon when set  
- Edges from relationship facts  
- Pattern ref: Obsidian graph **behavior** (navigate network), skin = our TOKENS — not their theme hex

### Focus mode

Hides binder + agent; manuscript only. Agent state preserved.

## Key interaction flows

### Continuity

1. User writes in editor  
2. User runs Continuity (top bar or agent)  
3. Marks appear on spans; proposals land in agent panel / sheet pending  
4. User Accepts bible changes; marks remain until next run or resolve rules  

### Co-write (P1b)

1. User asks in agent panel (“continue from cursor”, “alt dialogue”)  
2. Agent drafts **in panel**  
3. User **Apply** → preview → lands in editor at cursor/selection  
4. No background insertion  

### Review (P2)

1. User runs Review  
2. Structured findings list in panel  
3. Optional “propose sheet fix” → Accept path

### Concrete tokens (source of truth)

**[design/TOKENS.md](./design/TOKENS.md)** locks:

- primary / accent / canvas / surface hex values  
- semantic mark yellow/red (diagnostics only)  
- type scale (px) + manuscript size/measure  
- spacing (4px grid), radii, control heights, rail widths  
- breakpoints, z-index, motion  
- CSS variable names for web + port checklist  

Ports (Win/macOS/Linux/Android/iOS) copy **those names and values**, not freehand UI.

### Portability mandate (non-negotiable)

The design system must be **robust enough to port** the same product UX across:

| Target | Examples | Constraint |
|--------|----------|------------|
| Web | Vite SPA (MVP host) | Primary build |
| Desktop | Windows, macOS, Linux (e.g. Tauri/Electron later) | Same tokens + shell patterns; native window chrome only at shell edge |
| Mobile | Android, iPhone | Same components/tokens; **adaptive IA** (binder/agent as sheets/drawers), touch targets, safe areas |

**Rules so porting is real, not a rewrite:**

1. **Tokens first** — color, type, space, radius, elevation, z-index, motion as named tokens (platform-agnostic values). No hard-coded hex in feature components.  
2. **Primitives over pages** — features compose `ui/*` primitives; no one-off styled divs that only work in the web CSS layout of the day.  
3. **Layout ≠ skin** — shell regions (binder / editor / agent) are structural slots; each platform maps slots to nav patterns (rails vs tabs vs bottom sheets) without forking business UI.  
4. **Density + input modes** — comfortable (pointer) and touch densities; min hit target ≥44px on touch profiles.  
5. **Responsive breakpoints as first-class** — not “desktop only then patch.” Mobile: editor hero; binder/agent become overlays or tabs.  
6. **No web-only traps in the system** — avoid hover-only critical actions; keyboard *and* touch paths; prefer CSS logical properties / flex/grid patterns that map to native layout.  
7. **Icon + type via tokens** — system/UI font stacks with platform fallbacks; icons monochrome, SVG, recolorable.  
8. **Theme contract** — light/dark (and later system) from the same token sheets.  
9. **Screenshot / gallery targets** — document components at desktop + narrow mobile widths before calling the system “done.”  
10. **Shell adapters later** — web shell now; desktop/mobile shells swap chrome only; domain + most UI components stay shared.

MVP ships **web**, but every design-system PR is reviewed against “will this fight Tauri/iOS/Android later?”

### Principles

1. IDE-calm (dark default; light supported)  
2. Type hierarchy: chrome vs manuscript (separate sizes/fonts if needed)  
3. Continuity colors are **semantic-only** (never primary brand buttons)  
4. Density: comfortable chrome, airy manuscript; touch profile when needed  
5. Motion: minimal; respect reduced-motion  
6. No marketing / upgrade chrome  
7. **Portable by construction** — see mandate above  

### Primitives to build before features

`Button`, `IconButton`, `Input`, `Textarea`, `Toolbar`, `Rail`, `Drawer`/`Sheet` (mobile-ready), `ListRow`, `Badge`, `Tabs`, `ChatMessage`, `Composer`, `ProposalCard`, `ApplyCard`, `Mark` styles, `EmptyState`.

### Adaptive shell patterns

| Width | Binder | Agent | Editor |
|-------|--------|-------|--------|
| Wide desktop | Left rail | Right rail | Center |
| Narrow / tablet | Overlay or left drawer | Overlay or bottom sheet | Full |
| Phone | Bottom nav or hamburger → full-screen stacks | Full-screen agent route/sheet | Full-screen editor |

Focus mode still = editor only on every platform.

### Files (when coding)

```
docs/design/TOKENS.md          # CANONICAL values (colors, type, space…)
src/styles/tokens.css          # web export of TOKENS.md (implement Wave 2)
src/components/ui/*            # shared primitives — token refs only
src/components/shell/*         # web shell adapter first
# later: shell-desktop/, shell-mobile/ adapters — same slots
```

### Design QA

- [ ] Manuscript measure holds at common **desktop** widths  
- [ ] **Narrow width**: binder/agent accessible without breaking editor  
- [ ] Agent panel hide/show without layout jump disaster  
- [ ] Focus mode truly single-column  
- [ ] Mark colors ≠ accent buttons  
- [ ] Keyboard focus visible; touch targets adequate on narrow profile  
- [ ] No hover-only critical action  
- [ ] Pending/proposal UI readable but secondary to chat when idle  
- [ ] Tokens only — no raw hex in feature components  
- [ ] Light + dark both sane

## Steal for UI

Patterns only — **full URLs + our mapping** live in [design/REFERENCES.md](./design/REFERENCES.md).  
**Never** copy third-party hex; always [design/TOKENS.md](./design/TOKENS.md).

| Pattern | From (see REFERENCES) | Our skin |
|---------|------------------------|----------|
| Agent sidebar + composer | Claude / Cursor / VS Code | TOKENS chrome + agent slot |
| Focus = chrome hidden | Obsidian focus-style workspace | Focus mode + `color.canvas` / manuscript type |
| Clean type column | Novlr | `text.manuscript`, measure tokens |
| Binder / codex | Novelcrafter (lighter) | binder width tokens |
| Diagnostics underlines | IDE problems | `color.markYellow` / `markRed` only |
| Apply/diff cards | VS Code apply | Proposal/Apply cards via ui/* |

## Anti-patterns

- Three equal permanent panes with no hide  
- Gen widgets in the editor gutter as default  
- Modal spam per proposal  
- Loud brand orange over text  
- Wide unbroken 200-char lines  
- Hard-coded hex / default Tailwind greys/blues in features  
- “Looks like Obsidian” via guessed purple/grey instead of TOKENS + Focus mode

## N4 — SSR hydration flash (latent-trap-not-bug)

Claim: `rails.agent` seeds from `atDesk` via `useState(() => defaultRailsAt(atDesk))`, and the
`useSyncExternalStore` server snapshot (`() => true`, `getServerSnapshot`) returns wide for all media
queries, so a sub-1366 first paint would seed the rail open and flash before the first client commit
corrects it.

**Classified latent-trap, not a live bug.** The app is a pure client-side SPA: `main.tsx` uses
`createRoot(...).render()` into an empty `<div id="root">` with **zero `hydrateRoot`**. The server
snapshot branch is therefore dead in the running app — `getServerSnapshot` only runs under SSR/prerender
hydration, which never happens today. So it is not a current defect; it is a trap that becomes real the
day someone adds SSR/prerender. Correctly **not filed**; a naming comment was landed at `af8c0a3`
recording the precondition (`createRoot` today), the failure (narrow client would hydrate `atDesk=true`,
seed the rail open, flash), and the fix (seed from a client-correct source rather than the SSR-wide
snapshot).

## Retracted harness artifacts (4)

Four candidate findings were **withdrawn** because they were artifacts of the review harness, not
product defects. The mechanism was named so no one chases ghosts. Common root cause: **programmatic /
synthetic `.click()` did not drive React state** the way a real user click does, so state that appeared
"stuck" or "double-cycling" was the harness, not the UI. A concrete example on record: an apparent
"Night→Sepia→Night" theme cycle came from the operator's real clicks interleaving with the agent's
synthetic ones, not a real 2-state-only cycle; the companion open/toggle "click did nothing" was the
same synthetic-event limitation (verified against source, `aria-pressed` sync was correct).

root cause (synthetic-click not advancing React state) and the theme-cycle / companion-toggle examples

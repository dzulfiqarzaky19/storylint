# 08 — False state (controls and checks that lie)

**Scope:** the defect class that dominated density/honesty work: a control, status, check, or test that **asserts something untrue about itself**.  
**Authority:** evidence for ox/rat. Does **not** override [IA_MAP.md](../../IA_MAP.md) or ox rulings (`companion-one-assistant`, ghost silhouette).  
**Locks held:** three ecosystems · depth ≤3 · no new panels · Continuity = verb · Draft = prose · chapters never Canon.

## 1. Named class (literature / practice)

| Term | Who | What it covers | Maps to today’s scars |
|------|-----|----------------|------------------------|
| **False affordance** | Gaver (1991), after Gibson; Norman *DOET* | Looks actionable; action missing or different | Composer accepts text it will discard; nine “live” buttons while another lane owns the job |
| **Hidden affordance** | Gaver | Works, but no cue | Opposite problem (discoverability) |
| **Negative affordance** | UX practice (disabled/grey) | “You cannot” — honest only if true **and** explained | Disabled-without-reason feels broken (Silver; Smashing hide-vs-disable) |
| **Signifier without affordance** | Norman | Cue promises a capability that is not there | Badge/count/check name that does not measure what it claims (`inbox-wall` → Chat) |
| **Gulf of evaluation** | Norman | User cannot tell what state the system is in | Check face showing last success after a failed run |
| **Visibility of system status** | Nielsen H1 | UI must reflect real status in time | Stale “No issues found”; busy chrome that lies |
| **Optimistic UI (without rollback)** | Product eng practice | UI claims success before the server agrees | Success path drawn before failure returns; tests “green” on unloaded builds |
| **State integrity** / **honest UI** | Practitioner synthesis (this brief) | Umbrella: displayed control/status/check/test state matches reality | Whole day’s defect shape |

**Recommended house vocabulary (short):**

- **False state** — umbrella (control, status, check, or test).  
- **False affordance** — interactive control subtype.  
- **Stale status** — success/idle left up after a newer outcome.  
- **False signifier** — label/name/badge that does not match the measured thing.

Related but **narrower** (do not collapse into them): disabled-vs-hidden debates; pure optimistic UI (fine when rollback is honest); ghost-control **contrast** (silhouette must read as a control — ox AW — orthogonal to whether its *action* is truthful).

## 2. Three deliberate gaps — what mature tools do

### (a) Unsaved work on refresh

| Tool class | Pattern |
|------------|---------|
| Scrivener / Ulysses / Word desktop | Continuous local autosave + backups; crash recovery is expected |
| Google Docs / Notion | Cloud autosave; refresh restores |
| Obsidian / local markdown | Files on disk are truth; refresh is a non-event |
| Pure web apps without local draft | `beforeunload` nag — last resort |

**Practice verdict:** durability beats warning. Storylint’s **draft persistence over beforeunload** is the grown-up pattern for a local-first desk. Remaining honesty debt is only **visibility of restore** (“recovered unsaved draft”), not a modal wall.

### (b) Accumulating workbench (Lab) with no archive/delete

| Tool class | How “nothing leaves” is handled |
|------------|----------------------------------|
| Scrivener Research / corkboard | Move, trash, compile ignores research |
| Obsidian | Folders, tags, trash; vault grows; search is the exit |
| Roam / Logseq | **Daily/journal** structure = soft temporal decay (old days leave the front, stay searchable) |
| Notion / Apple Notes | Archive + Recently Deleted |
| Milanote | Board archive |

**Decay:** almost no serious creative tool auto-deletes thought by age. “Decay” that ships is usually **view decay** (recency sort, daily notes), not destruction. Long-term pressure is always answered with **archive/trash + search**, not a new top-level kingdom.

**IA pressure:** literature does **not** demand a fourth surface. Archive is a state of a Lab card/board (or a filter: Active / Archived), still Home → Lab → thing.

### (c) Long model job, single-lane assistant (~20s)

| Tool class | Pattern |
|------------|---------|
| Novel AI sidekicks (Sudowrite-class, Novelcrafter-class) | One generation stream; cancel; editor remains the product |
| ChatGPT-class web | One reply in-flight per thread; new thread for parallel |
| VS Code Copilot Chat (2026 docs) | Queue / steer / stop; optional multi-**session**; OS notify when done — still explicit session model, not dual mouths in one face |
| Response-time canon (Miller; Doherty ~400ms feedback; Myers progress) | &lt;1s snappy; ~10s needs continuous feedback; longer needs progress + freedom to leave the wait |

**Practice verdict:** single-lane is normal for one desk partner. Honesty requirements while blocked: **one busy lexicon**, visible progress, cancel/stop, and **manuscript still writable** (companion busy ≠ app freeze). Multi-run identity is a product-model upgrade (ox already rejected under current model), not a density fix.

## 3. Evaluation bar (for reviews / CALM)

A control or check fails **false state** if any is true:

1. It looks available and the promised action is no-op, discard, or other-lane-owned.  
2. It shows a success/idle outcome that is not the latest run’s outcome.  
3. Its name/badge measures a different surface than it claims.  
4. A test or budget check asserts a build/path it never loaded.

Pass only when **signifier ↔ affordance ↔ system state** agree at the moment of perception.

## Bottom line

> **False state** = the UI (or the check watching it) claims a world that is not true.  
> Fix honesty in place. Do not buy a fourth ecosystem to store the truth.

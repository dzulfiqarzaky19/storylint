# Adjudication — D5 “Canon sheet detail hijacks binder”

**Reviewer:** ox (design authority, no implement)  
**Date:** 2026-07-31  
**Inputs:** density audit D5 recommendation · IA_MAP §2 depth · §4.4 binder detail stack · dolphin Draft+sheet bleed note · D9 park/restore

---

## Verdict: **(a)** — D5’s fix is wrong; the ruling stands

| Claim | Hold? |
|-------|--------|
| Canon sheet = Level-3 **binder detail stack**, not center surface | **Yes — locked** |
| D5 fix “open sheet in center; map collapses/splits; binder stays list” | **Reject as architecture** |
| D5’s *pain* (list vanishes, form owns rail, center feels wrong) | **Real — fix under the stack** |
| Sheet form visible during **Draft** | **Separate bug** (mode bleed / park), not proof center should win |

Do **not** reopen “sheet as center work surface” without founder + full IA rewrite. Depth-3 accounting was not a technicality: it keeps **one center job per place** (Canon center = map of accepted truth) and stops Canon from becoming two peer apps (Map app + Sheet app).

---

## When editing Kael, is the map supporting context or dead weight?

**Mostly dead weight for field edit; useful as peripheral context only.**

| User action | Map helps? |
|-------------|------------|
| Edit name, aliases, summary, notes, facts keys | **No** — eyes are on the form |
| Add relationship / understand “who is Kael tied to?” | **Yes** — if map highlights Kael and quiets the rest |
| Propose edge from map chrome while form open | **Competes** — two loud jobs (D4 already targets propose fold) |

So the honest read is **not** “map must stay a full peer desk while the binder is a full editor,” and also **not** “therefore the form must take the center.”

It is: **form owns the binder stack; map should demote to context (or stay map-only when no sheet is open).**  
Eyes on the form do not require the form to colonize the center column. Email clients edit in the master-detail pane without promoting the message list’s sibling to “the whole window’s only truth.” Scrivener keeps binder structure left even when the editor is the prose job — here the **map** is Canon’s center job, and the **sheet** is the L3 thing you open from the navigator.

If we put the sheet in center:

- Canon gains a second primary work surface (map vs sheet) and restarts mode thrash.
- Binder becomes a dumb list only — weaker “bible binder” metaphor.
- Depth path Home → Canon → Sheet stays “3” on paper but **user attention** now treats sheet as a place swap equal to Draft/Lab.
- Map-as-Canon-entry (IA rename Graph → Canon map) loses its reason to own the fold.

That is a product reopen, not a density fix.

## What D5 actually is (smaller, true faults)

### F1 — Detail stack is not a stack (core D5)

Today: open sheet → binder **replaces** the list with a full edit form.  
“Back to binder” is a recovery hop, not a visible stack. User loses kind lists, counts, and adjacent sheets.

**Fix direction (under ruling):**

- Keep binder **in Canon list mode** with a push stack: list visible behind or one clear back chrome that never feels like leaving Canon.
- Prefer **list + detail** in the rail when width allows (selected row + form below/beside), or compact sheet header (`Kael · Character · Back`) that always restores the same scroll position.
- Do **not** move fields to center to “save” the list.

### F2 — Center stays loud while binder is 100% form

Map + open propose + kind filters + full network while the left rail is a dense form = **two desks**. Map is not helping the form fields, so it reads as hijack even though the form is “correctly” in the binder.

**Fix direction (under ruling, pairs with D4):**

- On sheet-open: **demote** map chrome (collapse propose if not already; optional dim / focus selected node; no new primary CTAs).
- Map remains center **identity** of Canon, not a second editor.
- foldOwner still map-or-sheet-context, never “form steals center.”

### F3 — Sheet chrome during Draft (dolphin note)

Kael form in the binder **while place = Draft** is not an argument for center sheets. It is **mode bleed**: Canon detail left mounted, or park/restore failed, or sheet open doesn’t require Canon place.

**Fix direction:** already aligned with D9 — leaving Canon parks sheet; entering Draft/Lab must show Draft/Lab binder lists, not a stranded sheet form. If density shot shows otherwise, file as **regression / park gap**, severity high, independent of D5 architecture.

## Why not (b)?

(b) says the ruling is wrong because eyes are on the form.  
Eyes-on-form is true; **eyes-on-form ≠ form owns the ecosystem center**. Draft owns center for prose; Canon owns center for the map of truth; the binder owns entity records as the bible spine. Breaking that to match a single screenshot’s eye track recreates Graph-as-peer / sheet-as-app.

If founder later wants **sheet-first Canon** (center editor, map as overlay), that is a **new IA**, not D5 density.

## Why not pure (c)?

(c) is emotionally right (“both pains real”) but operationally mushy.  
**Architecture pick must be single:** stack-in-binder.  
The split is only in **remediation layers** (F1/F2/F3), not in “maybe center sometimes.”

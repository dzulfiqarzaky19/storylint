## Context

T-005 fixed Windows EPERM on the project atomic rename with a path-keyed exclusive chain
covering load/save/update/switchFile across ProjectStore instances. The chain is keyed on the
path string in a module-level Map.

That makes correctness depend on a precondition: **every path that reaches ProjectStore for a
given physical file must be the same string**. Enforced by ProjectFileRoot + ProjectStore.open.

Junction measurement is evidence that path identity ≠ file identity, not a request to support
junctions.

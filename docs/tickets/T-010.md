## The actual finding

The base case fits by **1px** (on a 320px rail assumption). At the real desk floor the
agent rail is **272px** (`--size-agent` / `--size-agent-lg`); 320px is `--size-agent-2xl`
only. Empty five-face row already overflowed ~45px at 1366 before this fix.

Anything that grows the row re-triggers the clip:

| Grower | Effect |
|---|---|
| Inbox pending badge, 2 digits | Inbox tab grows; Research clips at rest |
| Badge, 3 digits | Worse, and was **unbounded** |
| Any i18n label | Near-certain without a density rule |
| A sixth face | Same |

**The badge is the common case, not an edge case.**

## Fix (rule, not arithmetic)

1. **Badge cap** — `pendingCount > 99 ? '99+' : pendingCount`
2. **Base Inbox max-width** — `.companion__face-inbox { max-width: 4.25rem; overflow: hidden }` at all breakpoints (was narrow-only 5.5rem)
3. **Dense resting chrome** — gap 2px, padding-inline `var(--space-1)`, sm font so five full labels fit 272px with headroom for the capped badge
4. **Geometry lock** — `e2e/t010-face-row-fit-smoke.mjs` fails if resting `scrollWidth - clientWidth > 1` or Research is clipped at desk. Phone documents badge + thin-scrollbar scroll affordance (40vw drawer cannot hold five full labels).

## Acceptance detail

- [x] Resting row keeps all five labels intact at desk rail width with a 2-digit pending badge
- [x] Fit defended by density + badge cap + inbox max-width (not 1px coincidence)
- [x] Geometry check fails on overflow (mutation prove: remove density → desk checks red)
- [x] Narrow branch verified: badge present, overflow discoverable via `scrollbar-width: thin`

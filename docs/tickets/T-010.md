## The actual finding

The base case fits by **1px**.

Five labels total 283px + gaps + 2×8px padding = **319px in a 320px rail**. That is not a fit,
it is arithmetic that has not failed yet. Anything that grows the row re-triggers the clip:

| Grower | Effect |
|---|---|
| Inbox pending badge, 2 digits | Inbox tab 54px → 86px (+32). `scrollWidth` 347 > 319 client. **Research clips ~28px at rest.** |
| Badge, 3 digits | Worse, and **unbounded** — see below |
| Any i18n label | Untested, but 1px of headroom means near-certain |
| A sixth face | Same |

**The badge is the common case, not an edge case.** An empty Inbox is the state dolphin could
reproduce without a seeder; a working session has pending items. So the state that clips is the
state users are usually in.

## Two things that make it worse than measured

**1. The badge count is uncapped.** `AgentPanel.tsx:482` renders `{pendingCount}` raw:

```tsx
{pendingCount > 0 ? <span className="companion__inbox-count">{pendingCount}</span> : null}
```

No `99+` clamp. Three digits is wider than dolphin's measured 2-digit case and nothing bounds it.

**2. The narrow branch already solved this; desk width never inherited the fix.**
`AgentPanel.css` under `@media (max-width: 767px)`:

```css
/* Keep Inbox badge visible; shrink label room if needed */
.companion__face-inbox {
  max-width: 5.5rem;
}
```

Someone already reasoned about badge growth eating the row — and scoped the guard to narrow only.
**The cleanest statement of this ticket: the fix exists, at the wrong breakpoint.**

## Why the existing mutation lock did not catch it

`checkTools.test.ts` → `MUTATION lock: face-tab clip fix keeps selected label fully on-screen`
is a **source-text assertion**. It reads `AgentPanel.tsx` / `AgentPanel.css` as strings and checks
that `scrollIntoView` is called, that `scrollLeft` is corrected both directions, and that the CSS
says `scrollbar-width: thin`.

It never renders anything, so it cannot fail on a clipped label. It also names a stronger claim
than it checks ("keeps selected label fully on-screen") — ox 8e, report strength ≤ check strength.
Filed separately as T-011; not this ticket's job.

Note also that `scrollbar-width: thin` is **not exercised at rest in the empty case**, because
nothing overflows. The affordance only appears once the badge pushes the row over.

## Acceptance detail

- [ ] Resting row (no face selected, no scroll) keeps all five labels intact at rail width with a
      2-digit pending badge
- [ ] The fit is defended by a **rule**, not by arithmetic. Options, in preference order:
      cap the badge (`99+`), give `.companion__face-inbox` a `max-width` at desk width as narrow
      already has, or let the Inbox label truncate before Research does
- [ ] A check that would **fail** if the row overflows at rest — measured geometry, not source text.
      A source assertion cannot catch this class; that is why it got here
- [ ] Narrow branch (`<767px`) verified too — dolphin is measuring it; fold the result in
